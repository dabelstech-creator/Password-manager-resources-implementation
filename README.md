# OpenAI Identity & Passkey Authentication Engine

An experimental Swift authentication-decision prototype packaged as a Vapor HTTP service for deployment on Render.

## Included

- Preserved `OpenAIProvider` simulation.
- Preserved `IdentitySystem` decision logic and action tokens.
- Vapor HTTP server with `/health` and `/auth/decision`.
- Docker configuration for Render.

## API

### `GET /health`

Returns a JSON health response.

### `POST /auth/decision`

Request:

```json
{
  "domain": "github.com",
  "password": "",
  "hasPasskey": false,
  "isBound": false
}
```

Response:

```json
{
  "action": "CREATE_NEW_PASSKEY",
  "domain": "github.com",
  "note": "Decision generated by the existing prototype logic; this endpoint does not verify WebAuthn credentials or perform an OIDC exchange."
}
```

Possible action values: `CREATE_NEW_PASSKEY`, `REBIND_PASSKEY`, `PASSWORD_POLICY_FAILURE`, `AUTHENTICATE_WITH_PASSKEY`, `AUTHENTICATE_WITH_PASSWORD`.

## Render

Use the repository root as Docker context and `./Dockerfile` as Dockerfile path. The server binds to `0.0.0.0` and reads Render's `PORT` environment variable (default 8080).

## Important security status

This remains an experimental decision engine, not a production identity provider. The OpenAI code exchange is simulated. The passkey action values are workflow decisions only: there is no WebAuthn challenge generation, attestation/assertion verification, credential storage, account binding, or session issuance. Do not use it to protect real accounts or process production credentials until those components are implemented and independently tested.
